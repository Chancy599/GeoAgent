# GeoAgent 流程与标签几何评测

## 生成和后修复

输入原图 → 自动检测线段、标签绑定和直角标记 → Geometry Agent 整理原图构造 → Code Agent 生成 TikZ → 确定性坐标后修复 → 编译、渲染与拓扑检查 → Critic 复核 → Supervisor 按需调度补测或修订。

- **Geometry Agent** 在首版 TikZ 之前核对原图，选择字母对应的实测点，说明哪些点相连、哪些边是虚线，并提交垂足及直角标记的两条射线。程序用原图笔画验证这些提议，保留有证据支撑的要求。拟合线段因虚线间隙而截短时，邻近线的交点可以补充端点候选。对于已测得的垂足，通用角标检测漏检时，程序会在垂足附近搜索原图的小方框笔画来核对朝向。
- **Code Agent** 根据共享点、必画边、线型和角标射线编写或修订 TikZ，同时处理标签排版和未纳入坐标契约的辅助构造。程序检查实际代码是否使用共享端点，接受同线型的共线分段。通过验证的垂足在写入坐标时按实测支撑线投影，并保留原像素测量。
- **Critic** 在每份成功渲染的新版本后自动核对原图与渲染。它检查漏画、错接、虚线端点、角标方向、标签及线宽，返回可执行的修改意见。遇到歧义时可从既有测量候选中确认连接或绑定，也可弃权。确认结果会触发代码复验。预算耗尽时，尚未完成复核或仍有必须修复问题的可用产物记为 partial。

构造计划、经验证的边和标记要求，以及每版检查结果保存在 `state.json`。

后修复从生成的数值坐标和线段提取候选。程序会先识别由两条主体长边支持的直角符号，排除其笔画及专用辅助点，并保护带标签的短线段。默认修复近平行和近垂直关系，角度容差为 0.5°。单点最大位移为图形对角线的 0.5%，已有边长最大变化为 1%，共线容差为 0.3%。曲线分支冻结曲线定义依赖及圆周、切线保护点，仅修复剩余点之间的近平行关系，共线容差为 0.2%。

参数见 `configs/default.json`。符号表达式、未支持的曲线和局部变换保留原样。导出回读或编译失败回退原始代码；内容与配置哈希防止重复写回。前置GES修复仍是显式可选实验设置，默认处理发生在TikZ生成之后。

## 参考清单：先提取，单独保存

运行`python scripts/build_geometry_reference.py --workers 20`，仅从`data/test/latex`提取，输出到`data/test/geometry_reference`。不访问生成结果，不根据预测筛选参考项。

`corrections.json`保存人工审核的参考构造修正，并用原始源码哈希防止误用。已审核修正6986的E：取BC与圆心O、半径OB的上半圆的第二交点，得到(-0.161002879, 2.995676563)。不修改原始TeX；原绑定保留在source_xy，所有依赖E的目标值在构建时重算。

`1269_s_fig2` 的原始 TeX 编译后，E 是沿 PC 从 P 出发遇到的第一个圆交点。参考解析使用这条路径的顺序，重算 E、依赖 E 的 M 和相应几何目标。规则按原始 TeX 哈希限定，仅作用于参考清单的解析。可在 [参考执行核验](../results/latest/reference_execution_audit.json) 查到坐标回读。

每图JSON包含：

- 可见标签及其显式绑定坐标、内部坐标别名和绑定表达式。
- 实际绘制、两端均有标签的直线段。
- 具有公共带标签顶点的线段对所定义的角度和有序长度比。
- 参考数值、源码哈希、解析规则哈希，以及重复标签与绑定冲突。

标签坐标按代码表达式解析，包括内部别名、字面坐标、受支持的calc和交点表达式；picture/scope变换及数值x/y坐标基会作用于坐标。字号、above/left、anchor、文字xshift/yshift属于排版，不修改at绑定。

`\coordinate (P7) at (2,3); \node[above] at (P7) {$A$};`提取A=(2,3)，不要求内部坐标名为A。同名内部坐标与可见标签绑定不同时，记录冲突，使用可见标签的实际绑定。无标签点、辅助点、曲线上的无标签点和隐式交点均不创建评测顶点。

重复标签若精确绑定同一点则合并；绑定不同点则该标签无法解析，不选择最近点。没有可见标签的命名坐标也不参与评测。无明确绑定的路径位置标签暂报告不支持，不将其误绑定到路径端点。

## 测量项的确定规则

当前协议为`label-bound-v1`，只有一套活动实现。

1. 对所有带标签点对，保留非退化且被直线笔画支持至少95%的线段；有中间标签的组合线段也保留，例如AM、MB、AB。
2. 对有一个公共端点的线段对，角度大于等于5°时记录角度，范围为0–180°；所有非退化线段对记录长度比。
3. 线段端点及线段对均按标签排序，比例方向固定，不按预测翻转分子分母。
4. 小正交注释路径经过几何过滤；圆、圆弧、填充与非顶点文字不作为直线测量项。只含曲线的图可以没有角度与比例。

角度MAE为预测与参考角度差的绝对值，单位度。比例MRE为`abs(预测比例/参考比例 - 1)`，表格乘100显示百分比。二者越低越好。

源代码可能包含近似构造或不一致的标签，清单反映源码实际写出的绑定，不自动纠正数据，不从原图猜测其意图。字面文字坐标若被作者用作排版偏移，当前规则也不会擅自吸附到附近点；可通过绑定审计发现这类样本。明确审核过的参考错误通过独立corrections.json修正，不能根据某个预测结果选择修正值。

## 评测时只读清单

`scripts/evaluate_structure_ab.py` 读取清单中固定的 150 个图名及对应 JSON，再读取每种方法的同名生成代码。角度、长度比和线段直接按标签名匹配。对齐后点位误差在匹配完成后，用共有标签拟合平移、旋转和统一缩放。

对每条参考测量项，取预测中的同名点，检查所需线段是否非退化且实际绘制，再计算角度或比例。缺标签、重复冲突、缺边、退化边与程序无法解析都记录不可用原因，不替代为零误差。即便某组缺少整份程序，也保留该图及全部参考测量项的分母。

主表固定纳入全部 150 图、4528 个参考角度和 5516 个参考比例。缺测角度计 180°，缺测比例计 100%，可测比例误差封顶 100%。每张图先按参考项平均，再对 150 张图等权平均。线段覆盖率按图平均，角度和比例覆盖率按完整参考项计数。逐图记录保留原始误差和缺测原因。

## CV坐标的程序化传递

`geometry.preserve_cv_coordinates=true`默认开启坐标传递约束，独立于几何修复开关。程序按`label_bindings`取得当前CV测得的坐标，使用统一缩放、平移与y轴翻转计算TikZ坐标，统一保留三位小数后插入图形开头。原始CV测量与内部求解保留浮点精度；程序导出和后修复写回均采用三位小数，每轴舍入误差不超过0.0005个TikZ单位。Geometry Agent提交的同名舍入点不覆盖原始测量，也不再作为重复点传入TikZ提示。模型负责连接、样式和辅助构造，不再计算这些点的坐标。

坐标契约支持单个大写字母标签和无歧义的有效测量点，包括从原图笔画拟合得到的交点。Geometry Agent 可以在生成前修正错绑或错读的标签。Critic 可在复核时补充纠正，程序会重验已有版本。歧义未解决的绑定、冲突点和缺测点由生成流程继续处理。受管理的标签必须引用同名坐标，普通标签排版偏移仍可保留。受管理坐标的重定义、坐标系变换和路径局部平移会触发重试。

坐标传递在确定性后修复之前完成。后修复仍有独立开关，求解器仍围绕其输入坐标做最小移动；已管理的点不再先经历模型的数值改写。后修复允许按现有限制改变这些坐标，这与生成时的数值传递属于不同阶段。每版的`tikz/vN/coordinate_contract.json`记录参与点、原始像素坐标、转换、排除原因；`unrepaired.tex`保存坐标写入后、约束修复前的代码。

通过 `GEOAGENT_PRESERVE_CV_COORDINATES=0` 可以单独关闭坐标传递约束。通过 `--no-geometry-repair` 可以单独关闭 TikZ 后修复。

后修复先以浮点精度求解，再按三位小数导出，并重新检查实际导出坐标的位移、边长变化、点在线段上的顺序和方向残差。方向残差门限受配置角度容差与坐标量化产生的长度相关误差界共同限制；不把内部解的零残差当作导出结果。失败则保留统一量化后的不修复代码。可运行 `python scripts/verify_current_repair_exports.py` 核对本批已接受的后修复关系。

## 垂足和折弯的处理边界

当前的垂足投影发生在坐标写入时。Geometry Agent 提交垂足关系后，程序核验原图的连接和支撑线。测得的垂足离投影点至多 6 像素时，写入投影坐标，并在证据状态保留原测量。后修复仍按自己的候选规则处理坐标。

`1251_s_fig3`、`1531_s_fig1` 和 `1630_s_fig1` 的折弯在后修复前就已出现。原图里相关笔画的方向一致，具名点偏离笔画中心线后，按点连接就产生了折弯。已有的后修复可以保护部分近似点线关系，当前流程尚未把 Geometry Agent 确认的整条直线统一送入共线求解。[样本复核](../results/latest/geometry_case_audit.md)

待验证的方案是由 Geometry Agent 确认原图上属于同一直线的笔画。程序用经验证的笔画拟合交点，必要时联合求解共线、点在线上和垂足关系。Code Agent 仍负责具名路径和实虚线分界，Critic 复核结果。真实折点需要保留，例如 `1369_s_fig1` 的 A。

## 运行与产物

```powershell
python scripts/evaluate_structure_ab.py `
  --group haiku-5.5=outputs/baseline/haiku-5.5 `
  --group gpt-5.4=outputs/baseline/gpt-5.4 `
  --group qwen3.5-plus=outputs/baseline/qwen3.5-plus `
  --group glm-5.3-flash=outputs/baseline/glm-5.3-flash `
  --group ours=outputs/ours `
  --workers 20 --out results/latest/structure.json
python scripts/merge_evaluation_results.py --geometry-only
```

源码或解析规则更新后应重新构建清单。manifest保存参考JSON和原始TeX哈希；评测核验JSON与规则版本，评测过程不重新读取源TeX。如需确认源TeX更新，应运行构建步骤。

视觉评测由 `scripts/evaluate_visual_cached.py` 生成 `results/latest/visual.json`，视觉与几何的联合评测命令见 [README](../README.md#评测与复验)。固定协议采用 1000 px 白底画布上的灰度 Gaussian SSIM，以及 ViT-L/14@224 CLIP 和 DINOv2-base CLS 特征的余弦相似度。五种方法都按相同的 150 张图取均值。特征缓存位于 `.cache/visual_evaluation`，按图片内容与编码配置哈希区分。

结果见 [150 图报告](../results/latest/report.md)。五种方法均覆盖同一批 150 张图。

`outputs/ours/` 保存 GeoAgent 的 PNG、TikZ 和逐图档案。`outputs/baseline/` 按模型保存基线 PNG 和 TikZ。五种方法的主表使用固定的全部 150 张图，覆盖率以完整参考清单为分母。当前评测集中在 `results/latest/`，运行中间文件存放在 `.cache/`。

当前参考还修正6983的圆心O和圆周点E；1630按实际坐标、411保留原代码。符号不产生角度真值。CV端点恢复只处理未绑定标签，已有交点绑定不会与噪声端点重新竞争；浅折线和经核验的符号方向以源图测量为依据，不自动拉成对角线。
