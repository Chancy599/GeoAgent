### 第 6 步：Supervisor 指定修复，TikZ 生成 v2

Supervisor 根据 A 与 F 的坐标，将 AF 延长到 y=254 的底边。其推导约为：

```text
m = (149.6 - 65) / (238.3 - 68.5) ≈ 0.498
x_G = 68.5 + (254 - 65) / m ≈ 448
G ≈ (448, 254) px
```

这一步不是调用新的坐标测量工具，而是主智能体在修复指令中给出几何外推位置。

**实际动作与传入参数**（摘自 `action_history`，`null` 表示该记录未提供有效值）：

```json
{
  "action": "run_tikz_agent",
  "params": {
    "mode": "repair",
    "use_image": null,
    "instruction": "Repair: extend segment A-F beyond F to point G on the base line y=254 (pixel coords). Line A(68.5,65) to F(238.3,149.6) has slope ~0.498, so it meets y=254 at x≈448 -> G ≈ (448,254) in pixels; use the same scale as v1 (0.012719 cm/px, bbox-centred as in the existing tex). Draw F-G dashed (same dash style as A-B and B-E) and place a vertex G on base line with label 'G' placed below the line. Keep all other elements unchanged."
```

`mode="repair"` 切换到修复模式。程序自动给 TikZ 大模型附加旧版完整源码、编译错误和警告、上一版 Critic 问题，同时继续提供对象、关系和风格参数。大模型提交完整修订文档，而不是只提交一小段补丁。
