# 1260_q_fig2 处理流程

输入一张几何图，经过 **CV 检测、Geometry 整理、TikZ 生成、Critic 评审与修复**，最终得到可编译的绘图代码。

![原图：注意 F 至 G 的虚线和 G 标签](D:/Users/18217/Desktop/我的文件/GeoAgent/outputs/presentations/1031汇报_images/00_input.png)

## 1. Supervisor 调用 CV，检测线段

Supervisor 收到任务、图片路径等信息后，选择 `call_cv_tool`。程序自动把当前图片交给工具：

```json
{
  "tool_name": "detect_lines",
  "params": {}
}
```

工具检出 **8 条线段**，将端点坐标、线型等结果写入 GES，并把摘要返回 Supervisor。例如下面分别是底边和左侧竖向虚线的检测结果：

```json
{
  "objects": [
    {
      "id": "seg_01",
      "coords": {"a_px": [643, 254], "b_px": [148, 254]},
      "style": {"line": "solid"}
    },
    {
      "id": "seg_06",
      "coords": {"a_px": [68.5, 59.6], "b_px": [68.5, 257.4]},
      "style": {"line": "dashed"}
    }
  ]
}
```

此时知道“哪里有线”，还没有完整确定它们与 A～G 的对应关系。

![线段检测结果](D:/Users/18217/Desktop/我的文件/GeoAgent/outputs/presentations/1031汇报_images/s02_lines.png)

## 2. Supervisor 调用 CV，将字母绑定到顶点

```json
{
  "tool_name": "bind_point_labels",
  "params": {}
}
```

工具建立字母与顶点的对应关系。Supervisor 后续指令使用的坐标为：

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| (68.5,65) | (68.5,254) | (635.5,254) | (352,65) | (162.9,254) | (238.3,149.6) |

**G 的字母被识别到了，但附近没有匹配到顶点，所以没有绑定 G 点。** ![标签绑定结果：G 未绑定到顶点](D:/Users/18217/Desktop/我的文件/GeoAgent/outputs/presentations/1031汇报_images/s03_labels.png)

## 3. Supervisor 委派 Geometry，整理对象与关系

调用 `run_geometry_agent`，向 Geometry 提供：

- **输入证据：** A～F 坐标、8 条线段描述。
- **任务指令：** 判断线段连接哪些点、F 是否在 AE 上、哪些线是虚线，并尝试解释未绑定的 G。

Geometry 调用大模型分析后，又调用两个本地工具补充证据：

| 工具 | 传入信息 | 结果 |
|---|---|---|
| `detect_right_angle_marker` | `roi=[0,0,1,1]`，检查整图 | 未检出方块直角标记 |
| `analyze_line_style` | AB、BE 附近及较长底边的 3 组线段端点 | 补充线型证据，底边线型仍有争议 |

## 4. Supervisor 委派 TikZ，生成 v1

调用 `run_tikz_agent`，设置 `mode="generate"`。

**传入信息：** GES 对象与关系、点坐标、实线/虚线列表、标签位置，以及程序测得的线宽、字号和建议尺度。指令要求画 A～F，并明确 AF 只画到 F。

TikZ 调用大模型生成完整源码，通过 `submit_tikz` 提交。程序自动编译 PDF、渲染 PNG、校验产物，返回：

```json
{
  "version": 1,
  "compile_ok": true,
  "validation_passed": true,
  "best_version": 1
}
```

**v1 可以编译，但没有 FG 虚线和 G 标签。**

## 5. Supervisor 委派 Critic，发现遗漏

调用 `run_critic`，要求重点检查线段延伸、虚线和标签位置。程序将**原图与 v1 渲染图**、GES 摘要及对象核对清单交给 Critic 大模型。

![首轮评审：左为原图，右为 v1，缺少 FG 和 G](D:/Users/18217/Desktop/我的文件/GeoAgent/outputs/presentations/1031汇报_images/compare_v1.png)

Critic 返回两个问题。下面保留实际问题描述和关键控制字段：

```json
{
  "version": 1,
  "assessment_score": 0.85,
  "issues": [
    {
      "type": "missing_element",
      "severity": "high",
      "object_ids": ["seg_AF"],
      "description": "The original continues the line from F to G on BC as a dashed segment. The render stops AF at F and has no dashed FG."
    },
    {
      "type": "missing_element",
      "severity": "medium",
      "object_ids": [],
      "description": "The label G is missing at the foot of the dashed line on BC, to the left of C."
    }
  ],
  "actionable_counts": {"high": 1, "medium": 1, "low": 0},
  "must_repair": true
}
```

## 6. Supervisor 给出修复位置，TikZ 生成 v2

Supervisor 沿 A(68.5,65) 与 F(238.3,149.6) 的连线外推到底边 `y=254`，得到 **G≈(448,254) px**。

随后调用 `run_tikz_agent`，设置 `mode="repair"`，要求：

> 沿用 v1 的尺度，在 F 与 G 之间补画虚线，在底边下方补 G 标签，其余元素保持不变。

**TikZ 同时收到：** G 的位置、旧版完整源码、GES 对象与关系、Critic 问题、编译反馈和风格参数。大模型提交完整修订文档，新增的关键代码为：

```latex
\coordinate (G) at (1.221,-1.202);
\draw[dash pattern=on 3pt off 2pt] (F) -- (G);
\node[below] at (G) {$G$};
```

## 7. Critic 复核 v2，更新最佳版本

Supervisor 再次调用 `run_critic`，重点检查 FG 虚线是否延伸到底边，以及 G 标签是否补齐。

![第二轮评审：左为原图，右为 v2，FG 和 G 已补齐](D:/Users/18217/Desktop/我的文件/GeoAgent/outputs/presentations/1031汇报_images/compare_v2.png)

```json
{
  "version": 2,
  "assessment_score": 0.93,
  "issues": [],
  "must_repair": false
}
```

本轮未发现需修复问题，Runner 将 `best_version` 更新为 2。

## 8. Supervisor 调用 finish，归档结果

Supervisor 提交完成总结、`status="success"` 和未决项。系统归档最佳 tex、PDF、PNG 及状态、日志。
